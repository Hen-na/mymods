# Разборы песен: Cloudflare Worker + Genius API

Пошагово, минут на 20. Деньги: **0** — и Cloudflare, и токен Genius бесплатные.
Карту привязывать не нужно, заявку никто не рассматривает — токен выдаётся сразу.

Пока этого не сделано, окно `lyrics.txt` показывает данные о треке и ссылки.

---

## Что появится в окне

**Не текст песни.** Genius не отдаёт тексты через API ни на каком тарифе — у них
договоры с издателями, и передавать тексты дальше они права не имеют. Это не
ограничение, которое снимается деньгами: поля с текстом в ответе просто нет.

Что API отдаёт официально и что попадёт в окно:

- **«О песне»** — описание, которое пишет редакция и участники
- **Разборы строк** — цитата строчки и объяснение, что она значит, откуда
  отсылка, что имелось в виду
- **Credits** — продюсеры, авторы и все роли, которые заполнили на Genius:
  сведение, мастеринг, запись, оформление обложки, режиссёр клипа. Плюс альбом
  и студия, если указаны
- **Connections** — что песня семплирует, где семплировали её, каверы,
  ремиксы, интерполяции — со ссылками на эти песни
- дату выхода, обложку, ссылки на YouTube и Spotify, ссылку на страницу с
  полным текстом

Воркер забирает до 25 разборов, а в окне показывается пять случайных. Кнопка
**Other lines** тасует их заново, не делая нового запроса — каждый раз другой
угол песни.

Ограничение намеренное: несколько процитированных строк с разбором — это
комментарий, а вся песня целиком была бы обходом лицензии. Поменять числа можно
в `MAX_ANNOTATIONS` (в воркере) и `ANNOTATIONS_SHOWN` (в `assets/js/blog.js`).

## Зачем воркер

Токен опознаёт **тебя**, а не данные. Положишь его в страницу — кто угодно
заберёт из исходника и будет тратить твой лимит, а отвечать по условиям
использования будешь ты. Плюс `genius.com` вообще не разрешает запросы со
сторонних страниц: из браузера напрямую не выйдет при всём желании.

```
браузер  →  твой воркер (токен тут)  →  Genius API
```

---

## Шаг 1. Токен Genius

1. Зайди на <https://genius.com/api-clients> (нужен обычный аккаунт Genius)
2. **New API Client** — название и адрес сайта, любые
3. После создания нажми **Generate Access Token**
4. Скопируй **Client Access Token** — это он и нужен

Именно Access Token, а не Client ID и не Client Secret.

---

## Шаг 2. Аккаунт Cloudflare

Зарегистрируйся на <https://dash.cloudflare.com/sign-up>. Домен подключать не
надо: воркер получит бесплатный адрес вида `genius-proxy.твой-логин.workers.dev`.

---

## Шаг 3. Разрешённые сайты

Открой [`genius-proxy.js`](genius-proxy.js), найди в начале `ALLOWED_ORIGINS` и
проверь, что твои адреса на месте:

```js
const ALLOWED_ORIGINS = [
  'https://www.heppa.online',
  'https://heppa.online',
  'http://localhost:8099'
];
```

Без этого списка любой сайт сможет гонять запросы через твой токен.

---

## Шаг 4. Публикация

Нужен [Node.js](https://nodejs.org/). Проверить — команда `node -v`, должна
напечатать версию.

> **Windows, важно.** В PowerShell `npx` скорее всего откажется работать:
> *«npx.ps1 cannot be loaded because running scripts is disabled on this
> system»*. Пиши **`npx.cmd`** вместо `npx` — это тот же npx в виде bat-файла,
> на который запрет не действует. Либо открой вместо PowerShell обычный
> **cmd.exe** (Win+R → `cmd`).
>
> Если в приглашении стоит `>` и любая команда отвечает `SyntaxError` — ты
> внутри Node, он ждёт JavaScript. Выйти: `.exit`

**Все команды выполняются из папки `worker`** — там лежит `wrangler.toml`.
Сначала перейди в неё:

```bash
cd C:\Users\heppa\mymods\worker
```

> Если запустить из другой папки, wrangler не найдёт конфиг и пойдёт искать его
> по окрестностям — а в домашней папке упрётся в `C:\Users\heppa\Application
> Data` и остановится с *«A permission error occurred while accessing the file
> system»*. Это невидимая папка-ссылка родом из Windows XP, она закрыта на
> чтение у всех. Права и антивирус ни при чём — просто зайди в `worker`.

Дальше:

```bash
npx.cmd wrangler login
```

Откроется браузер — разреши доступ. Затем:

```bash
npx.cmd wrangler secret put GENIUS_TOKEN
```

Вставь токен из шага 1 и нажми Enter. Он уйдёт в хранилище Cloudflare, в файлах
репозитория его не будет. И наконец:

```bash
npx.cmd wrangler deploy
```

В конце команда напечатает адрес воркера — скопируй.

---

## Шаг 5. Подключить к сайту

В `assets/data/posts.js` найди `window.GENIUS_API` и вставь адрес:

```js
window.GENIUS_API = 'https://genius-proxy.твой-логин.workers.dev';
```

Готово. Выбери трек в CD Player — в окне появится описание и разборы.

---

## Про лимиты

Genius не публикует точных цифр, но ограничение по частоте запросов есть.
Воркер кэширует ответы на сутки: один и тот же трек, запрошенный сто раз,
стоит одного обращения к API.

Расход видно в панели Cloudflare (Workers → твой воркер → Metrics).

---

## Если что-то не работает

Открой адрес воркера в браузере:

```
https://genius-proxy.твой-логин.workers.dev/?artist=Radiohead&track=Creep
```

| Что видно | Что это значит |
|---|---|
| `Forbidden` | Открыл напрямую — так и задумано. Проверяй с самого сайта |
| `{"error":"no_key"}` | Не выполнен `wrangler secret put GENIUS_TOKEN` |
| `{"error":"bad_token"}` | Токен неверный или отозван |
| `{"error":"not_found"}` | Песни нет на Genius — бывает с редкими треками |
| JSON с `description` | Всё работает |

Если по ссылке выше всё хорошо, а на сайте пусто — почти наверняка твой адрес
не попал в `ALLOWED_ORIGINS`. В консоли браузера (F12) будет слово CORS.

Пустое `description` и пустой список `annotations` — не ошибка: у малоизвестных
треков на Genius их часто просто нет. Окно тогда покажет ссылки.

## Гостевая книга

Тот же воркер умеет вторую вещь: хранить записи гостевой книги в настоящей базе,
чтобы их видели все посетители, а не только тот, кто написал. Свежие записи
показываются пузырями в боковой колонке на главной.

Хранилище — **D1**, это SQLite у Cloudflare. Бесплатно: 5 млн чтений и 100 тыс.
записей в сутки. Взял его, а не хранилище «ключ-значение», по одной причине:
если двое подпишутся одновременно, при KV одна запись молча потеряется, а D1
такого не допускает.

### Шаг 1. Создать базу

Из папки `worker`:

```bash
npx.cmd wrangler d1 create hennablog
```

Команда напечатает кусок конфига с `database_id`. Скопируй его в `wrangler.toml`:

```toml
[[d1_databases]]
binding = "DB"
database_name = "hennablog"
database_id = "сюда-то-что-напечатала-команда"
```

> ⚠️ **`binding` должен быть ровно `DB`.** Это имя, под которым код ищет базу
> (`env.DB`). `database_name` — наоборот, любое, это просто название базы в
> панели Cloudflare. Если вписать в `binding` имя базы, воркер её не найдёт и
> форма ответит «the D1 binding is missing».

### Шаг 2. Создать таблицу

```bash
npx.cmd wrangler d1 execute hennablog --remote --file=schema.sql
```

### Шаг 3. Два секрета

```bash
npx.cmd wrangler secret put IP_SALT
```

Любая длинная случайная строка. Ею подсаливаются адреса посетителей: воркер
считает, сколько записей пришло с одного адреса, но сам адрес нигде не хранится —
только необратимый хэш.

```bash
npx.cmd wrangler secret put ADMIN_TOKEN
```

Твой пароль для удаления записей. Придумай длинный и никому не показывай.

### Шаг 4. Выложить и подключить

```bash
npx.cmd wrangler deploy
```

В `assets/data/versions.js` впиши адрес воркера — это включит пузыри на главной:

```js
window.GUESTBOOK_API = 'https://genius-proxy.твой-логин.workers.dev';
```

Форма в блоге подхватит адрес сама: она берёт его из `window.GENIUS_API`
в `posts.js`, который у тебя уже прописан.

### Как удалить чужую запись

Узнать номера записей:

```
https://genius-proxy.твой-логин.workers.dev/guestbook
```

Удалить (подставь свой токен и номер):

```bash
curl -X DELETE -H "X-Admin-Token: ТВОЙ_ТОКЕН" "https://genius-proxy.твой-логин.workers.dev/guestbook?id=5"
```

Без верного токена удаление не работает, а если `ADMIN_TOKEN` не задан вовсе —
удаление выключено полностью, а не открыто для всех.

### Что стоит на пути спама

- одна запись в минуту и не больше пяти в сутки с одного адреса;
- потолки длины: имя 40 символов, сообщение 500;
- скрытое поле-ловушка, которое заполняют только боты — такие записи
  выбрасываются, но отправителю отвечают «успешно», чтобы бот не подстраивался;
- HTML нигде не исполняется, текст вставляется как текст.

Это отсекает автоматику. От человека, который вручную напишет гадость, спасёт
только удаление — для того и токен.

### Если что-то не работает

| Что видно | Что это значит |
|---|---|
| `{"error":"no_database"}` | В `wrangler.toml` нет блока `[[d1_databases]]` или не сделан деплой |
| `{"error":"guestbook_failed"}` | Таблицы нет — не выполнен `d1 execute` со `schema.sql` |
| `{"error":"too_fast"}` | Сработало ограничение: минута между записями |
| `{"error":"forbidden"}` на удалении | Неверный `X-Admin-Token` |

---

## Как убрать

Сотри адрес в `posts.js`:

```js
window.GENIUS_API = '';
```

Сайт вернётся к ссылкам. Сам воркер удаляется в панели Cloudflare.
